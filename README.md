# Landmark-test WebApp

Landmark-test WebApp は，Cai et al.（2013）の Landmark Task に基づき，水平線の中央判断と線同士の接触判断を体験し，回答，正答率，反応時間，課題の開始・終了時刻を記録する Web アプリケーションである．

中央判断（LM），接触判断（LMC），安静（Rest）を 1 セットとし，通常は 6 セット，合計 144 問を実施する．練習は設けず，開始前の説明を確認した後に本番へ進む．1 セットまたは 3 セットの短縮体験にも対応する．

HTML，CSS，JavaScript で構成し，PC のブラウザからローカルで利用できる．記録はブラウザ内に保持し，試行 CSV，イベント CSV，設定・全記録 JSON として保存できる．アプリのバージョンは `1.0.0` である．

## プロジェクトについて

本アプリは，視空間注意に関する Landmark Task の課題構成を体験し，課題成績と実施時刻を確認するために使用する．

扱う条件は以下の 3 種類である．

| 条件 | 内容 | 回答 |
|---|---|---|
| LM：中央判断 | 縦線が水平線の正確な中央にあるかを判断する． | 中央にある／中央にない |
| LMC：接触判断 | 縦線が水平線に接触しているかを判断する． | 接触している／接触していない |
| Rest：安静 | 画面中央の＋を見て休む． | 回答しない |

**1 ブロック**は，同じ条件を継続する区間を指す．LM と LMC は各ブロックで 12 問を出題し，Rest は 21.6 s の安静区間とする．通常の 6 セットでは，LM，LMC，Rest を各 6 ブロック，合計 18 ブロック実施する．課題前の指示は，対応する LM または LMC ブロックに含めて管理する．

本アプリ単独で記録・集計するのは課題成績である．脳活動の計測機能，左右半球の優位性の判定機能，外部センサとの接続機能は実装していない．センサデータとの対応付けには，出力した時刻情報を使用する．


各ファイルの役割は以下である．

## 利用するWeb API

本アプリでは外部ライブラリを使用せず，ブラウザ標準の機能を利用する．

| 機能 | 用途 |
|---|---|
| SVG | 水平線と縦線を描画する． |
| `requestAnimationFrame` | 描画更新に合わせて課題の進行を管理する． |
| Performance API | 刺激提示，回答，イベントの経過時間を記録する． |
| Web Crypto API | 出題順の生成に使用する乱数シードを取得する． |

| Fullscreen API | 開始時の全画面表示と，全画面解除の検出に使用する． |
| Page Visibility API | タブが非表示になったことを検出する． |
| Blob・URL API | CSV と JSON のダウンロードファイルを生成する． |
| HTML `dialog` 要素 | 設定，採用条件，中止確認のダイアログを表示する． |

課題の実施とデータ出力にインターネット接続は不要である．原著論文へのリンクを開く場合と，本 README の技術バッジを表示する場合はインターネット接続を使用する．

## 課題条件

### LM：中央判断

水平線と，水平線を横切る縦線を表示する．参加者は，縦線が水平線の中央にあるかを判断する．

1 ブロック 12 問の配分は以下である．

| 縦線の位置 | 水平線の全長に対するずれ | 問題数 |
|---|---:|---:|
| 中央 | 0 % | 6 |
| 左 | −2.5 %，−5.0 %，−7.5 % | 各 1 |
| 右 | ＋2.5 %，＋5.0 %，＋7.5 % | 各 1 |

ずれ量は，水平線の全長に対する，中央からの横方向の変位の比率である．例えば，水平線が 600 px の場合，2.5 % のずれは中央から 15 px の変位に相当する．

### LMC：接触判断

水平線の上方に縦線を表示し，縦線の下端が水平線に接触しているかを判断する．横位置ではなく，接触の有無に回答する．

| 接触状態 | 中央の問題数 | 中央以外の問題数 | 合計 |
|---|---:|---:|---:|
| 接触している | 3 | 3 | 6 |
| 接触していない | 3 | 3 | 6 |

中央以外の 6 問は，左右それぞれ 2.5 %，5.0 %，7.5 % の位置を各 1 回使用する．この 6 位置をシャッフルし，接触と非接触へ 3 位置ずつ割り当てる．

### Rest：安静

画面中央に＋を表示する．参加者は回答せず，21.6 s の間，注視点を見る．

### 出題順

LM と LMC の各ブロック内で，問題数の配分を保ったまま出題順をランダム化する．セッションごとに乱数シードを生成し，シードと全試行の出題順を JSON に保存する．

## 課題の進行と所要時間

開始前の説明を確認して「本番を開始」を押すと，以下の順に自動で進行する．練習は実施しない．

| 順番 | 内容 | 予定時間 |
|---|---|---:|
| 1 | LM の指示 | 4 s |
| 2 | LM：12 問 | 21.6 s |
| 3 | LMC の指示 | 4 s |
| 4 | LMC：12 問 | 21.6 s |
| 5 | Rest | 21.6 s |
| 合計 | 1 セット，24 問 | 72.8 s |

各問題は，**刺激提示 1.6 s ＋空白 0.2 s**で構成する．最後の問題の後にも 0.2 s の空白を設ける．回答しても刺激を消さず，回答速度によって次の問題の開始時刻を早めない．

| 設定 | LM | LMC | 合計問題数 | 予定所要時間 |
|---|---:|---:|---:|---|
| 1 セット：短縮体験 | 12 問 | 12 問 | 24 問 | 72.8 s，約 1 分 13 秒 |
| 3 セット：短縮体験 | 36 問 | 36 問 | 72 問 | 218.4 s，約 3 分 38 秒 |
| 6 セット：通常 | 72 問 | 72 問 | 144 問 | 436.8 s，約 7 分 17 秒 |

所要時間には各課題前の指示と最後の Rest を含み，開始前の説明・設定，一時停止時間は含めない．実際の所要時間にはブラウザの描画更新による遅れが加わるため，予定時間と完全には一致しない．

## 刺激の表示

刺激は SVG で描画し，正答に応じた色の変更や，本番中の正誤フィードバックは設けない．

| 項目 | 初期設定 |
|---|---|
| 水平線の長さ | 通常 600 px．初回はウィンドウ幅に応じて短くする． |
| 縦線の長さ | 40 px |
| 線の太さ | 2 px |
| 線の色 | `#151515` |
| 課題画面の背景 | 白 |
| LM の縦線 | 水平線を上下に横切る． |
| LMC の接触刺激 | 縦線の下端を水平線の高さに合わせる． |
| LMC の非接触刺激 | 縦線の下端を水平線の高さから 8 px 上方に配置する． |

非接触時の 8 px は，SVG 上の水平線の中心線と縦線の下端との距離を指す．線の太さを含む見た目の隙間とは異なる．

水平線の長さを変更しても，縦線の長さ，線の太さ，非接触時の距離は固定する．水平線の長さと SVG の左右余白が画面幅に収まらない場合は，開始を止め，長さの変更を促す．

## 回答操作

PC のキーボードで，左手の人差し指と中指を使用する．

| キー | 使用する指 | LM | LMC |
|---|---|---|---|
| F | 左手人差し指 | 中央にある | 接触している |
| D | 左手中指 | 中央にない | 接触していない |

回答受付は，刺激を提示している 1.6 s の間に限定する．

- 1 問につき最初の有効な回答だけを採用する．
- キーの長押しによる繰り返し入力を除外する．
- 指示画面，空白，Rest，一時停止中の入力は回答として採用しない．
- 期限内に回答しなかった場合は，無回答として記録する．
- 回答後も予定した刺激提示時間を維持する．

保存するキーコードは，F が `KeyF`，D が `KeyD` である．画面上の回答ボタンやタッチ操作による回答は実装していない．

## 表示・実施設定

開始画面の「表示・実施設定」から以下を変更できる．

| 設定 | 範囲・選択肢 | 用途 |
|---|---|---|
| セット数 | 1，3，6 | 通常実施と短縮体験を切り替える． |
| 水平線の長さ | 240～900 px，10 px 刻み | 画面に合わせて表示サイズを調整する． |
| 観察距離 | 10～300 cm，任意入力 | 画面から目までの距離を記録する． |
| 測った水平線の長さ | 1～50 cm，任意入力 | 定規で測った実寸を記録する． |

観察距離と実寸を両方入力すると，以下の関係から視角の目安を表示する．

```text
視角［°］＝ 2 × atan（水平線の実寸 ÷（2 × 観察距離））× 180 ÷ π
```

観察距離と実寸の入力は，記録と視角の確認に使用する．入力に応じて表示サイズを自動補正する機能は設けていない．プレビューを定規で測り，水平線の長さを手動で調整する．

「全画面で開始」は開始画面から切り替える．全画面表示を利用できない場合は，通常表示で開始する．

## 一時停止・中止

### 一時停止

「一時停止」を押した場合に加え，以下を検出した場合にも自動で一時停止する．

| 検出内容 | 記録する理由 |
|---|---|
| 手動の一時停止 | `manual` |
| タブが非表示になった | `tab_hidden` |
| ウィンドウからフォーカスが外れた | `window_blur` |
| ウィンドウサイズが変わった | `viewport_resize` |
| 全画面表示を解除した | `fullscreen_exit` |
| 中止確認ダイアログを開いた | `abort_dialog` |

「続ける」を押すと，中断した区間の残り時間から再開する．刺激提示中に一時停止した場合は，その試行に `interrupted = true` を設定する．中断した試行は出題し直さず，CSV に残したうえで成績集計から除外する．

### 中止

「中止」を押すと確認ダイアログを表示する．「中止して結果を見る」を押すと，その時点までの記録を保持し，結果画面へ移動する．

刺激提示中に中止した試行は `status = aborted` として保存し，成績集計から除外する．まだ提示していない問題の試行行は作成しないが，予定した全出題順は JSON に保持する．

## 結果の集計

結果画面では，LM と LMC を分けて以下を表示する．

| 項目 | 内容 |
|---|---|
| 正答率 | 正答数 ÷ 有効試行数 × 100 |
| 正答数 | 有効試行のうち，回答と正答が一致した問題数 |
| 誤答数 | 有効試行のうち，回答したが正答と一致しなかった問題数 |
| 無回答数 | 有効試行のうち，期限内に回答しなかった問題数 |
| 除外数 | 中断・中止等により集計から除外した問題数 |
| 平均 RT | 有効な正答試行の反応時間の平均，単位は ms |
| 中央値 RT | 有効な正答試行の反応時間の中央値，単位は ms |

**有効試行**は，記録が確定しており，中断・中止による除外対象ではない試行を指す．無回答は正答率の分母に含める．有効試行がない場合の正答率と，有効な正答がない場合の反応時間は「—」と表示する．

LM については，中央，左 2.5 %，右 2.5 %，左 5.0 %，右 5.0 %，左 7.5 %，右 7.5 % の各条件について，有効試行数，正答率，平均 RT を表示する．

このほかに，参加者 ID，記録した問題数，完了ブロック数，一時停止回数，完了・中止・中断の状態を表示する．完了ブロック数には Rest を含むため，6 セットを完了した場合は 18 ブロックとなる．

## 保存データ

結果画面から，以下の 3 ファイルを個別にダウンロードできる．ファイル名にはアプリが生成するセッション ID を使用し，参加者 ID はデータ内に保存する．

| 保存ボタン | ファイル名 | 内容 |
|---|---|---|
| 試行 CSV を保存 | `<session_id>_trials.csv` | 1 試行 1 行の刺激条件，回答，正誤，反応時間，提示時刻 |
| イベント CSV | `<session_id>_events.csv` | 指示・刺激・空白・安静の開始終了，回答，一時停止，再開，中止 |
| 設定・全記録 JSON | `<session_id>_session.json` | 設定，シード，全出題順，試行記録，イベント記録，採用条件 |

CSV は UTF-8 BOM 付き，カンマ区切り，CRLF 改行で出力する．各セルを二重引用符で囲み，値に含まれる二重引用符をエスケープする．表計算ソフトで数式と解釈される可能性がある文字列には，先頭にアポストロフィを付ける．

### 試行CSV

| 列名 | 内容 |
|---|---|
| `session_id` | セッション ID |
| `participant_id` | 参加者 ID．未入力の場合は `anonymous` |
| `condition` | `LM` または `LMC` |
| `cycle` | セット番号 |
| `block` | Rest を含む全体のブロック番号 |
| `trial_in_block` | ブロック内の問題番号，1～12 |
| `trial_number` | セッション全体の問題番号 |
| `offset_ratio` | 水平線の全長に対する中央からのずれの比率．左は負，右は正 |
| `offset_direction` | `left`，`right`，`center` |
| `contact` | 接触の有無，`true` または `false` |
| `expected_answer` | 正答，`yes` または `no` |
| `response` | 回答，`yes` または `no`．無回答は空欄 |
| `response_key` | `KeyF` または `KeyD`．無回答は空欄 |
| `correct` | 正答は `true`，誤答は `false`．無回答は空欄 |
| `rt_ms` | 刺激提示開始から回答までの時間，単位は ms．無回答は空欄 |
| `onset_timestamp` | 刺激提示開始の日時 |
| `onset_elapsed_ms` | 刺激提示開始時のセッション経過時間 |
| `planned_onset_ms` | 出題計画上の刺激提示開始時刻，セッション開始基準の ms |
| `offset_timestamp` | 刺激提示終了の日時 |
| `offset_elapsed_ms` | 刺激提示終了時のセッション経過時間 |
| `actual_display_ms` | 一時停止時間を差し引いた提示区間の実測時間，単位は ms |
| `response_timestamp` | 回答日時 |
| `interrupted` | 中断または中止による除外対象か |
| `interruption_reasons` | 中断理由．複数ある場合はセミコロンで連結 |
| `status` | `answered`，`no_response`，`aborted` |

`offset_ratio = -0.025` は左 2.5 % を表す．`block` は Rest を含むため，例えば 2 セット目の LM は 4，LMC は 5 となる．Rest 自体は回答を伴わないため，試行 CSV の行を作成しない．

### イベントCSV

共通列は以下である．イベント固有の項目は追加列として保存し，該当しない行では空欄とする．

| 列名 | 内容 |
|---|---|
| `session_id` | セッション ID |
| `participant_id` | 参加者 ID |
| `event` | イベント種別 |
| `timestamp` | イベントの日時 |
| `elapsed_ms` | セッション開始からの経過時間 |
| `condition` | `LM`，`LMC`，`Rest`．該当しない場合は空欄 |
| `block` | ブロック番号．該当しない場合は空欄 |
| `phase` | `instruction`，`stimulus`，`isi`，`rest`．該当しない場合は空欄 |

| イベント種別 | 内容 | 主な追加列 |
|---|---|---|
| `session_start` | セッション開始 | なし |
| `phase_start` | 各区間の開始 | `planned_onset_ms`，`planned_duration_ms`，`onset_delay_ms` |
| `phase_end` | 各区間の終了 | `actual_duration_ms`，`aborted` |
| `answer` | 有効な回答の受付 | `trial_number`，`response`，`key` |
| `pause` | 一時停止 | `reason` |
| `resume` | 再開 | `pause_duration_ms` |
| `session_abort` | セッション中止 | `reason` |
| `session_end` | 全予定区間の完了 | なし |

`onset_delay_ms` は，一時停止を含むセッション経過時間と予定開始時刻との差である．`actual_duration_ms` も一時停止を含むため，一時停止がある場合は描画遅延だけを表す値ではない．

LM・LMC の課題部分を抽出する場合は，指示に相当する `instruction` と，課題中の `stimulus`・`isi` を区別する．Rest の開始・終了時刻は，`condition = Rest`，`phase = rest` の行から確認できる．

## 時刻形式

日時は，UTC の ISO 8601 形式で保存する．末尾の `Z` は UTC を表し，日本標準時で確認する場合は 9 時間を加える．

```text
例：2026-10-21T06:00:00.000Z ＝ 日本標準時 2026-10-21 15:00:00.000
```

時刻管理には `performance.now()` と `requestAnimationFrame` のコールバック時刻を使用し，`performance.timeOrigin` と組み合わせて日時へ変換する．

セッション開始は，開始ボタンを押した瞬間ではなく，最初の指示区間を開始した時点を基準とする．`elapsed_ms`，`onset_elapsed_ms`，`offset_elapsed_ms` は，この開始からの経過時間であり，一時停止時間も含む．

ブラウザが記録する時刻は，画面上の物理的な発光開始時刻を直接測定した値ではない．外部センサの記録と対応付ける場合は，UTC／日本標準時の違い，計測端末間の時計のずれ，描画・入力の遅延を考慮する．

## 端末内保存

`localStorage` に以下の情報を保存する．

| 保存キー | 内容 |
|---|---|
| `landmark-cai-settings-v1` | 表示・実施設定 |
| `landmark-cai-session-v1` | 直近 1 セッションの状態，試行記録，イベント記録 |

課題の区間切り替え，回答，一時停止，再開，終了等に合わせてセッションのスナップショットを保存する．前回の記録がある場合は，開始画面の「記録を見る」から結果を表示し，データをダウンロードできる．

再読み込み後の機能は，保存済み記録の閲覧・出力である．途中のセッションを再開する機能は設けていない．保存時点で刺激提示中だった試行は，記録の復元時に `page_reload` を中断理由として追加し，集計から除外する．終了時刻等が未確定の場合は，該当する列に未設定の値が残る．

新しい本番を開始すると直近セッションの保存内容を上書きするため，必要な記録は次の本番の前にダウンロードする．「前回の記録があります」の「削除」はセッション記録を削除し，表示・実施設定は保持する．

ブラウザの設定やプライベートモードによっては保存できない場合がある．ローカルファイルで開く場合の保存領域はブラウザの実装に依存するため，`localStorage` を唯一の保存先とせず，終了後に CSV・JSON を保存する．実験記録を外部サーバへ送信する処理は実装していない．

## データフロー

1. 参加者 ID と表示・実施設定を確認する．
2. 乱数シードを生成し，指定セット数の出題計画を作成する．
3. LM の指示・12 問，LMC の指示・12 問，Rest を順に実施する．
4. 各試行の刺激条件，回答，正誤，時刻を記録する．
5. 区間の開始終了と，中断・再開等をイベントとして記録する．
6. 進行中の記録を `localStorage` に保存する．
7. 完了または中止後に，有効試行から条件別の成績を集計する．
8. 試行 CSV，イベント CSV，設定・全記録 JSON を出力する．

## 使用方法

### 1．WebAppを開く

同じフォルダに `index.html`，`style.css`，`script.js` があることを確認し，`index.html` をダブルクリックして PC のブラウザで開く．

### 2．参加者IDを入力する

開始画面の参加者 ID 欄に識別子を入力する．入力は任意であり，空欄の場合は `anonymous` として記録する．

### 3．表示・実施設定を確認する

「表示・実施設定」からセット数と水平線の長さを選択する．必要に応じて観察距離と実寸を入力し，「設定を適用」を押す．短く動作を確認する場合は 1 セットを選択する．

### 4．本番を開始する

左手人差し指を F キー，中指を D キーに置く．「全画面で開始」を必要に応じて切り替え，「本番を開始」を押す．

### 5．課題に回答する

指示画面で判断内容を確認する．LM は中央かどうか，LMC は接触しているかどうかに，F＝はい，D＝いいえで回答する．Rest 中は＋を見て回答せずに休む．

### 6．必要に応じて一時停止・中止する

一時停止後は「続ける」を押す．実施を終了する場合は，「中止」から「中止して結果を見る」を選択する．

### 7．結果と記録を保存する

結果画面で条件別成績と実施状況を確認し，以下を保存する．

- 試行 CSV
- イベント CSV
- 設定・全記録 JSON

### 8．次の本番を開始する

必要なファイルを保存した後，「開始画面に戻る」を押す．参加者 ID と設定を確認してから，次の本番を開始する．

## 原著と本アプリの設定

Cai et al.（2013）の方法記述を基に課題を構成する．原著に記載された条件と，体験用アプリとして定めた内容を以下に示す．

| 区分 | 内容 |
|---|---|
| 原著に基づく課題構成 | LM・LMC 各 6 ブロック，安静 6 ブロック，LM・LMC は各ブロック 12 試行 |
| 原著に基づく時間 | 課題前の指示 4 s，刺激提示 1.6 s，課題ブロック 21.6 s |
| 原著に基づく刺激条件 | LM は中央 50 %・非中央 50 %，ずれ量は左右 2.5 %・5.0 %・7.5 %．LMC は接触 50 %・非接触 50 % |
| 原著に基づく回答指 | 左手人差し指で肯定，左手中指で否定 |
| アプリで採用する刺激間隔 | 12 試行で 21.6 s とする構成に合わせ，刺激提示後に 0.2 s の空白を設ける． |
| アプリ独自の進行 | 「LM → LMC → Rest」の固定順，Rest は 21.6 s，1・3 セットの短縮体験，練習なし |
| アプリ独自の表示・操作 | 中央の＋の見た目，線の色・太さ・縦線長・非接触時の距離，F／D キーの割り当て |
| アプリ独自の配分・記録 | ブロック内の位置別配分，回答受付期限，一時停止・除外方針，CSV・JSON 出力 |

原著の方法欄では，安静ブロックの秒数と，全 18 ブロックの厳密な提示順序までは確定できない．そのため，本アプリの予定所要時間 436.8 s を，原著実験の確定した所要時間として扱わない．

原著の水平線は 15 cm，視角は 8°である．本アプリでは px 単位で表示し，実寸と観察距離は任意で記録するため，初期設定のままで原著の視角を再現するものではない．

## 注意点

- PC と物理キーボードを使用する．スマートフォン向けの回答 UI は設けていない．
- 提示時間と反応時間はブラウザ上で管理するため，ディスプレイの更新周期，端末の負荷，ブラウザの処理時間の影響を受ける．
- 一時停止がある場合は予定時間より長くなる．刺激提示中に中断した試行は，回答済みであっても成績集計から除外する．
- 水平線の px 値だけでは実寸や視角を保証できない．表示条件をそろえる場合は，画面の拡大率，実寸，観察距離を確認する．
- CSV の日時は UTC である．日本標準時のセンサログと結合する場合は，同じ時刻基準に変換する．
- `localStorage` に保持するセッションは直近 1 件である．次の本番を開始する前に必要なファイルを保存する．
- ページを再読み込みした場合は保存記録を確認できるが，その途中から課題を継続できない．
- 未提示の問題は試行 CSV に含めない．予定した全刺激の確認には JSON の `trial_order` を使用する．
- 本アプリの成績だけから，脳活動の左右差や半球優位性を判定しない．
